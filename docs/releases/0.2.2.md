# MCseg 桌面版 0.2.2：把 H&E 解卷積修正併進乾淨發布基底

日期：2026-09-20。

## 為什麼需要 0.2.2

0.2.1 出現了兩個內容不同的版本，這是本版存在的唯一理由：

| | `feat/tauri-desktop-packaging` @ `8d63d2d` | `master` @ `573d8bc`（標籤 `desktop-v0.2.1` 於 `f73665f`） |
|---|---|---|
| H&E 解卷積修正 | 有 | **沒有**（仍為 `inv(M).T`） |
| `test_17_color_deconvolution.py` | 有 | 沒有 |
| `tauri.conf.json` 版本 | 0.2.1 | 0.2.1（由 `a64a35a` 另一路徑獨立 bump） |
| 發布工具鏈 | 舊 staging 腳本 | 新版（tracked-files 驅動、拒絕 dirty build、`BUILD_MANIFEST.json`、`THIRD_PARTY_NOTICES.md`、`finalize-release.mjs`） |

`master` 已被標成 `desktop-v0.2.1`，卻不含 0.2.1 存在的理由（H&E 修正）；
而除了這個修正之外，`master` 全面較新——`a64a35a` 是把打包分支併回 `master`
的 merge commit，之後又加上發布產物清理與授權聲明。

因此 0.2.2 ＝ `master` 的發布基底 ＋ `8d63d2d` 的 H&E 修正。
刻意不沿用 0.2.1 版號，避免「同一個 0.2.1 有兩種內容」在日後追查雜湊時誤判。

## 本版內容

- `backend/src/segmentation/cellpose_runner.py`：移除 `color_deconvolution_he`
  多餘的逆矩陣轉置。染色向量按 row 排列，`OD = C @ M`，故 `C = OD @ inv(M)`。
  詳見 `docs/color_deconvolution_fix.md`。
- `backend/tests/test_17_color_deconvolution.py`：正向 Beer-Lambert 合成的回歸測試。
- 桌面殼版本 0.2.1 → 0.2.2（`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`），
  讓 bootstrap 的 `.resource_version` 比對觸發後端資源更新。
- Python API health 的 `0.8.0` 是另一個版本欄位，不代表桌面殼升級失敗。

歷史分割結果不會自動改變。本次沒有重跑 b00、模型推論或重新評估 AP。
此修正會改變使用 Hematoxylin 通道的後續輸入。

## 建置方式

建置需求與產物驗證規則見 `docs/desktop-build.md`（未改動）。

```powershell
cd frontend
npm ci
npm run tauri:build:windows
```

`build-windows.ps1` 會在 sidecar 缺少時自行取得並驗證 uv 0.12.5，
強制使用 Windows 專用 Cargo target，只產出 NSIS EXE，
再由 `finalize-release.mjs` 把 EXE、`.sha256` 與 `.build.json` 落到 `release/`。
`release/` 不納入 Git。

## 安裝後驗收

```powershell
$runtime = Join-Path $env:APPDATA 'com.mcseg.app\app'
Get-Content (Join-Path $runtime '.resource_version')
Get-FileHash (Join-Path $runtime 'backend\src\segmentation\cellpose_runner.py') -Algorithm SHA256
Get-FileHash .\backend\src\segmentation\cellpose_runner.py -Algorithm SHA256
Invoke-RestMethod http://127.0.0.1:8001/api/health
```

驗收條件：marker 為 `0.2.2`、兩個 Python SHA-256 相同、health 正常、
UI 能開啟並正常關閉後端。另以自選小 ROI 驗證 H&E 分割，
保存新輸出，不覆蓋歷史基準。
