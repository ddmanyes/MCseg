# 5. MPS Batch-Size Safety Clamp Applies Uniformly to CLI and API

Full-slide segmentation on Apple Silicon (MPS) reliably OOMs above `batch_size=2`; the API path already force-clamps to `min(batch_size, 2)` regardless of what the caller requested. When this clamp moved into the shared `run_full_slide_segmentation` function (consolidating orchestration previously duplicated between `api/segmentation.py` and `cli/segment.py`), we decided the clamp must apply unconditionally to the CLI path too, even though CLI users can pass an explicit `--batch-size` and may run on non-Mac GPUs where the clamp is unnecessary. We chose safety and behavioral consistency between the two entry points over CLI power-user throughput, since the project's stated execution environment is macOS (`CLAUDE.md` §1) and a silent OOM crash is worse than a silently-capped batch size. If a real non-Mac, high-throughput CLI use case emerges, revisit this with a platform-detection guard rather than removing the clamp outright.
